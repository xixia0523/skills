# Android 源码调用链研究

调用链研究只在用户显式输入 `$android-call-chain` 时开展。若本 Skill 被隐式加载而用户没有显式调用，不要套用调用链研究流程。

目标是基于不可变源码基线还原一条实际主链：从用户指定的上层 API 出发，追到承担该调用语义的责任终点，再按 API 契约及本次观察目标追踪受理结果、业务返回值、回调或状态事件，形成可审计闭环。不要把所有可能实现分支罗列成“完整调用链”。

## 安装与更新

用户要求安装或更新本 Skill 时，先阅读 [references/install.md](references/install.md)。在下载或申请安装写入权限前，检查实际目标路径及当前会话报告的同名安装。发现已有安装时停止，给出已核实的绝对路径、供用户在本机终端手动删除该 Skill 的命令，以及删除后重新发送的标准 GitHub 安装消息；不要自行删除、改名、替换、覆盖或通过临时安装绕过冲突，也不要申请删除或替换权限。确认不存在旧安装后，直接使用 Codex 内置 `skill-installer` 安装。

## 输入门禁

开始前必须获得：

- 准确 API 或调用代码，足以确定类、方法和重载；
- Android 版本。

仅在会改变主链选择或证据结论时补问调用场景。自研框架还需要源码位置和 commit；第三方 SDK 还需要依赖坐标及版本，并在可用时取得源码或二进制路径。

版本处理规则：

- 精确 Android tag 或可映射到源码清单的 build ID 优先；
- 只有 Android 大版本时，默认选择该版本的官方基础发布，先查证实际 tag 及其存在性，再解析 commit，不直接拼接标签；明确给出的次版本或季度版本也应保留，具体规则见 [source-routing.md](references/source-routing.md#基线解析)；
- 解析并记录实际使用的不可变 commit。多仓库调用链分别记录各仓库 commit，不用浮动分支替代。

如果缺少必填输入，先询问缺失项，不要开始猜测式分析。如果已有信息足以锁定基线，但设备配置、feature flag、HAL 类型或构建事实会在多个实现之间改变实际主链，先做可用的只读检查；仍无法判定时只追问决定分支所需的最小事实。

## 多 Agent 协作

每次请求与返回/回调分析均由主 Agent 理解任务，通过与用户的多轮对话澄清影响分析的需求；信息充分后拆分任务、编排依赖，至少安排两个研究子 Agent 并发取证，并另设独立 Review Agent 对照源码复核。主 Agent 维护共同源码基线，汇总产物、核对段落衔接并统一报告。只补问影响选路或结论的缺失信息，不要求固定对话轮数。

Review Agent 不兼任被审内容的研究作者，必须直接读取固定版本源码，核对正文、图、摘录和结论；无源码依据的实现描述须在原处说明缺失原因及影响，正式契约与旁证按证据类型区分。修订后的事实及其依赖关系须再次复核，复核状态与闭环等级分别记录。具体编排与交付要求见下列协作指南。

## 开始分析

每次任务都先阅读：

- [references/source-routing.md](references/source-routing.md)：确定 AOSP、Kernel、Vendor、自研和第三方源码从哪里取证；
- [references/evidence-policy.md](references/evidence-policy.md)：按逐跳标准证明进程、线程、边界和闭环等级；
- [references/source-walkthrough.md](references/source-walkthrough.md)：组织请求与返回每一步的源码摘录、执行时序和阅读续接。
- [references/multi-agent-workflow.md](references/multi-agent-workflow.md)：澄清需求、编排并发研究、汇总证据并执行独立源码复核。

报告以 [assets/call-chain-report-template.md](assets/call-chain-report-template.md) 为起点，按实际链路增删内容，不保留占位符。

## 工作流

1. 锁定准确重载、调用场景、源码归属和版本基线，并明确 API 契约承诺及本次观察目标是受理/投递确认、业务完成还是状态事件。把初始化链压缩为前置条件，除非它直接决定当前请求的路由或返回语义。
2. 建立源码基线清单。所有源码链接固定到 commit；tag、build ID、设备 fingerprint 和配置事实另列，不能互相替代。
3. 从生产代码的调用点向下追踪。结合源码配置、运行时 flag 和设备事实选出唯一主链。未选分支只说明排除依据，不并列展开。
4. 为每一跳记录调用双方、参数或数据形态变化、同步性、进程、源执行上下文、切换机制和目标执行上下文。在每个 R/S 步骤中按调用下潜或返回恢复顺序展示调用点与必要实现，并就近讲解每段源码：简单逻辑简述作用，复杂逻辑讲清关键条件、数据变化和执行机制。一个步骤涉及多个调用时，先在父步骤说明整体功能及内部函数调用链，再按需以 `R8.1`、`R8.2` 或 `S8.1`、`S8.2` 等子步骤展开。第三章请求链、第四章响应链涉及驱动或内核时，在各自相关源码前增加局部调用图，标明进程、线程、用户态/内核态、同步调用、异步投递及等待/唤醒续接；组织细则见 [source-walkthrough.md](references/source-walkthrough.md)。
5. 遇到 Binder、Handler、Executor、JNI、HAL、socket 或 syscall 边界时，必须分别给出边界两端证据。不能只因命名、架构常识或相邻层接口而补出中间箭头。
6. 按 API 语义和本次观察目标选择责任终点：只承诺受理/投递的 API 可止于权威受理实现；纯本地 API 可止于权威本地实现；系统状态止于权威系统服务；硬件操作止于可证明的驱动/固件实现或正式契约；网络调用止于设备侧请求与服务端响应契约。不要为了“完整”强行追到内核。
7. 从责任终点追踪约定的可观察结果，明确它是受理状态、同步返回、Binder reply、callback、Future、广播还是状态事件。仅承诺投递且不提供完成通知的接口，追踪投递成立及调用方的返回/传输确认，不虚构业务 reply，不将契约未承诺的回调列为缺口。若本次目标明确要求业务完成，则继续证明该目标；无法观察或证明时说明限制，不能用投递成功代替业务完成。
8. 只补充会改变完成语义的异常、权限拒绝、超时、取消、进程死亡、Binder death 和资源清理路径。
9. 主 Agent 汇总各研究产物并核对接缝，填完证据账本；独立 Review Agent 对照固定源码审计每条箭头、正文讲解和摘录的版本、上下文与时序，核对局部图的执行上下文、等待条件及请求/响应续接。主 Agent 修订后回交复核，记录最终稿的复核状态，并按证据策略给出 `SOURCE-CLOSED`、`CONTRACT-CLOSED` 或 `OPEN-GAP`。
10. 有匹配设备时，可用 adb、日志或 Perfetto 验证分支与时序；没有真机也应完成静态分析。动态结果只作旁证，不能替代源码证据。

## 主链纪律

- 正文只呈现与指定基线和前置条件一致的一条主链。
- 若静态源码无法区分 AIDL/HIDL、binderized/passthrough、不同 HAL 或 feature flag，实现分支尚未锁定；不要任意挑选。
- 无法证明的跳转明确标为 gap，不用测试、文档、trace 或反编译结果伪装成生产源码。
- 静态源码不能证明具体线程 ID 时，只写可证明的执行上下文，例如“调用线程”“Binder worker”“主 Looper”或“指定 Executor”。
- 初始化、缓存命中、懒加载和异步排队等前置状态必须与主链假设一致。

## 输出

默认使用中文，源码符号保持原文。将完整报告写入当前工作区：

```text
docs/call-chains/<api>-<variant>-<baseline>.md
```

`<api>` 使用可辨识的 `Class.method`；`<variant>` 包含重载参数类型及影响主链或观察目标的场景标识，例如 `String-cache-miss`；`<baseline>` 使用核实后的 tag，若只有 commit 则用其短哈希。文件名中的其他不安全字符替换为 `-`，完整方法签名和场景仍须写入报告正文。

写入前检查目标文件。只有本次任务是修订该报告，且其完整签名、源码基线清单、选路前置条件及观察目标与本次一致时，才原地更新；范围不同或无法确认时另起文件。可用由上述范围信息生成的短摘要作为区分后缀；仍重名时延长摘要或增加后缀，保留已有分析。已有范围明确的报告修订可沿用原路径。

报告至少包含源码基线、前置条件、完成/观察目标、唯一主链时序图、请求链、响应链、失败与清理、底层概念简释、证据账本、Agent 分工与独立源码复核记录，以及闭环结论。

请求链和响应链默认采用逐步源码导读：每个步骤配有对应的源码调用、固定版本出处、详略适当的源码讲解及后续步骤或返回续接位置。多调用步骤在展开源码前提供整体功能、内部调用链及子步骤导航。涉及驱动、内核的段落采用“局部调用图 → 执行与等待说明 → 源码导读”的阅读顺序，第三、第四章分别展示请求推进和结果恢复，不能只用第二章总时序图代替。源码不可见的部分明确展示可用契约与缺口，按证据策略定级。具体组织方式见 [source-walkthrough.md](references/source-walkthrough.md)。

对话中只返回主链摘要、闭环等级、关键 gap（如有）、独立复核状态及报告路径。不要只在对话中给出分析而省略报告文件。
