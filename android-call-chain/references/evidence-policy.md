# 证据与闭环策略

报告的基本单位不是“找到一个同名符号”，而是一条有方向的调用箭头。每条主链箭头都必须能回答：谁在何处以什么数据调用谁，是否跨边界，在哪个执行上下文继续，结果如何回来。

## 证据等级

从强到弱使用以下类型，并在账本中明确标注：

- `SOURCE`：固定 commit 的生产源码、生成接口源码或构建配置；用于证明实际调用与实现。
- `CONTRACT`：固定版本的 AIDL/HIDL、UAPI/正式头文件、稳定 SDK 或协议契约；用于封闭不可见实现边界。
- `BINARY`：与目标版本匹配的 AAR/JAR/SO 反编译、符号或反汇编；只能作降级证据。
- `RUNTIME`：adb、日志、Perfetto、binder trace 或设备状态；用于确认选路和时序。
- `CORROBORATION`：测试、示例和说明文档；只作旁证。

架构常识、命名相似和非目标版本源码不构成该箭头的证据。`RUNTIME`、`CORROBORATION` 不能替代缺失的 `SOURCE` 或 `CONTRACT`。

描述当前实现的事实、图中箭头和源码讲解均须能回溯到证据。没有源码依据时，在相关位置说明未取得、访问受限、实现闭源或尚未证实的具体原因及影响范围，不能以确定语气保留猜测，也不能把无法取得源码写成源码不存在。正式契约只支持其覆盖的外部语义，必须标明实现不可见；推导、反编译和教学示意按实际来源标识。

## 逐跳证明

普通函数调用至少记录调用方的 call site，以及被调用方的声明或实现；若动态分派决定主链，还要证明实际接收者。参数重命名可简写，但跨序列化、单位换算、坐标变换、ID 映射、缓存或聚合时必须写明数据变化。

每条证据记录：

- 步骤 ID 与方向（请求/响应）；
- caller 与 callee 的完整符号；
- 源进程和目标进程；
- 源执行上下文、切换机制、目标执行上下文；
- 同步、异步、oneway 或阻塞等待语义；
- 输入/输出及关键数据变化；
- 固定源码 URL、仓库 commit、文件、符号、行号和证据类型。

一条箭头涉及多个源码点时，可在同一账本行列出多条证据，也可拆成连续步骤，但不能把未证明的中间层压成一个箭头。

## 源码导读审计

按 [source-walkthrough.md](source-walkthrough.md) 展示各 R/S 步骤，并逐段核对：

- 摘录语句、符号、条件和原始行段与所指 commit 一致；本地修改过的源码另行记录工作树状态或内容摘要。行号与内容匹配，不能只检查链接能够打开。
- 本步有实际调用点及必要实现；复用前文实现时，有当前调用语句、参数与上下文，并能跳到被复用的源码。源码不可见时明确可用调用点、契约和缺口。
- 每段源码有就近讲解：简单逻辑交代作用与去向，复杂逻辑结合当前路径解释关键条件、数据或状态变化、执行交接及返回恢复。
- 多调用步骤在子步骤及源码前说明整体功能与内部函数调用链；调用层级、交接方式和子步骤映射与源码一致，R/S 两侧均可据此导航。
- 省略范围没有掩盖决定选路、返回值或清理时机的语句。生成规则推导、教学示意和反编译片段的标识与来源相符。
- 请求的暂停位置与响应的恢复位置能够对应；投递与消费两端有证据，跨线程依赖没有被表述为未经证明的绝对时序。
- 涉及驱动/内核的连续子链在第三、第四章各有局部调用图；图中函数、队列、等待条件、通知来源和恢复入口可对应 R/S 步骤及其源码。教学骨架已按实际路径重画，缺口没有被示意箭头掩盖。

推导片段不能单凭其外观当作生产生成物。接口、固定生成器和必要构建条件足以证明的语义可依其底层证据审计；未知条件影响关键路径时应保留 gap。可用索引或内容摘要辅助复核大量摘录，但这些辅助文件不能证明调用关系，也不改变闭环等级。

## 边界证明

### Binder

按主链实际范围证明 client call/proxy、AIDL/HIDL transaction 或接口定义及传输边界；主链进入服务端执行时，再证明 server stub/实现。按接口约定证明 reply/callback 或提交确认。`oneway` 不预设业务 reply，只有接口另有完成通知时才证明相应反向入口。同步 Binder 调用通常由 client 调用线程阻塞等待、server Binder worker 执行；嵌套事务可能在原调用线程中重入，`oneway`、线程池配置或实现再次投递也会改变语义，必须以目标版本代码为准。callback 入口不等于外层调用栈恢复；到 client stub 后若再投递 Handler/Executor，分开记录两次交接。

### Handler、Looper 与 Executor

给出 `post`/`sendMessage`/`execute`/调度点和实际 handler、looper、executor 或调度器的来源。无法静态确定具体线程时，只写“主 Looper”“指定 Executor”“Binder worker”“调用线程”等可证明上下文，不猜线程名或线程 ID。

### JNI

同时证明 Java/Kotlin native 声明、静态/动态注册映射和 native 实现。动态注册需定位注册表与加载路径；只有同名 native 符号不足以证明映射。

### HAL

证明 framework/native client 选择的接口版本与实例、transport 边界和实际 service/implementation。若只能看到稳定 AIDL/HIDL 契约而实现闭源，在请求语义及该接口约定的返回/通知均被契约覆盖时以 `CONTRACT` 封口；接口未承诺业务通知时不额外要求。

### Syscall、socket 与驱动

同时证明用户态发起点和内核入口、驱动 file operation、协议端点或正式 UAPI。一次 `ioctl` 或 socket write 不是天然终点；终点取决于 API 承诺的语义。若内核、固件或远端只可通过契约观察，按契约覆盖范围决定是否闭环。

## 进程与线程判断

进程归属应来自 manifest `android:process`、service 发布/查找、启动代码、进程入口、设备 service 列表或等价生产配置。包名、目录名和类名本身不能证明进程。

线程沿调用栈保持不变，直到出现有证据的调度或 IPC 边界。静态证据通常只能证明执行上下文类别，不能证明某次运行的线程 ID。Binder、Looper 和 Executor 的默认行为也必须与该版本实现及配置一致。

## 责任终点与返回闭环

责任终点由 API 对调用方承诺的可观察语义决定：

- 仅承诺受理/投递：完成该承诺的权威受理实现及其返回/提交确认；
- 纯计算、本地缓存或进程内状态：产生权威结果的本地实现；
- 系统管理 API：拥有权威状态或执行动作的系统服务；
- 硬件 API：被选中的 HAL/驱动/固件实现，或覆盖该语义的正式接口契约；
- 网络/远端 API：设备侧发出的最终请求以及把远端响应交回本地的正式协议/SDK 契约。

在报告范围中明确 API 契约承诺及本次观察目标。仅承诺受理/投递且本次目标也止于此的接口，证明投递成立及调用方的返回或传输确认即可形成该范围的闭环；不能据此声称业务已完成，也不因接口未承诺完成通知而判为缺口。需要业务完成或状态事件时，同步返回追踪 return/reply，异步通知追踪 callback、Future completion、广播或状态事件；仅证明请求已发送不足以满足这些目标。用户明确要求更深的观察目标但缺少证据或可观察入口时，保留该目标的限制或 gap，不能自行缩小范围后宣称闭环。

## 闭环等级

- `SOURCE-CLOSED`：选定观察目标的请求及约定的返回/通知全部由固定版本生产源码证明，边界两端没有实质缺口。
- `CONTRACT-CLOSED`：选定观察目标的请求及约定的返回/通知链完整，但至少一个闭源边界只能由匹配版本的正式接口契约封口。
- `OPEN-GAP`：责任终点、实际分支、任一关键箭头或返回路径既无足够源码，也无完整正式契约。

`BINARY` 可以缩小 gap，不能单独提升为 `SOURCE-CLOSED`；仅有运行 trace、测试或文档时仍为 `OPEN-GAP`。结论按整条链最弱的关键证据定级，并逐项列出 gap 对可确认结论的影响。

## 独立源码复核

按 [multi-agent-workflow.md](multi-agent-workflow.md) 另设独立 Review Agent，直接读取与报告相同 commit 的原始源码或匹配版本契约，逐项核对正文、全部 R/S 及子步骤、图、讲解、证据账本和闭环结论。子 Agent 摘要、多 Agent 一致意见和链接可达性不能代替源码核实。

复核记录包含受审正文版本、源码基线、覆盖范围、问题定位与依据、处理状态及剩余缺口。主 Agent 修订后，Review Agent 复核变更及相关上下游；最终报告必须与实际受审内容一致。“已复核 / 部分复核 / 未复核”描述复核覆盖与问题处理，不能替代或提高闭环等级；明确披露缺口的 `OPEN-GAP` 报告也可以完成复核。

## 完成前审计

- 主 Agent 已明确需求并统一各研究任务的源码基线；并发片段的请求/响应接缝、数据和场景已核对。
- 时序图每条主链箭头都有证据账本步骤 ID。
- 请求链到达本次观察目标的语义责任终点，响应链回到调用方可观察点；受理闭环与业务完成闭环的表述一致，未要求契约未承诺的通知。
- 每次跨进程、跨线程、托管/原生、用户态/内核态边界都有两端证据。
- 进程、线程、同步性和数据变化没有超出证据。
- 底层局部图没有将内核态画成独立进程/线程；实际异步执行上下文、投递与消费、条件已满足的路径，以及阻塞后的唤醒、调度和条件检查均与源码一致，请求等待点与响应恢复点可互相定位。
- 选定基线中的配置与 flag 足以排除其他实现；否则已补问或标记 gap。
- 异常、超时、取消、死亡和清理只覆盖会改变完成语义的路径。
- 所有源码引用都含仓库、commit、文件、符号和对应行号；动态证据与静态证据分栏说明。
- 每个实际展开的 R/S 步骤及子步骤均有源码导读与详略适当的讲解，或明确的契约/缺口说明；仅作总览的多调用父步骤说明整体功能，并通过内部调用链导航到子步骤证据。摘录内容与固定版本一致，省略和片段来源标识清楚。
- 请求与响应的暂停/恢复位置可续接，必要清理和异步完成已展开；步骤导航、时序图与证据账本可互相定位。
- 最终稿有独立源码复核记录，问题修订与受影响部分已回交复核；无法证实的实现描述已就近标注限制或 gap，未复核部分没有标成已复核。
